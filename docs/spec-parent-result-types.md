# 《大人考试》父母结果类型

## Goal

先建立可审阅的父母结果数据库，再把 10 个真实场景的选择，收束为一个可传播、可解释、数据驱动的最终结果：一个主型父母、一个影子父母、一笔具体的时间账单、一段真实后来，以及一张“如果当时支持”的幻想身份卡。

16 种父母名称全部保留在结果类型库中，由每个原子分支通过 `parentTypeId` 引用；它们不再作为 30 张平级结果卡直接堆叠给用户。

## Non-goals

- 不把结果变成“合格/不合格”的道德评分。
- 不删除现有三类卡的内部统计：成长卡、留下的卡、幻想卡仍用于解释和收集。
- 不把父母类型硬编码在 JavaScript 中；类型、文案和场景映射全部来自 JSON 数据表。
- 本阶段不接入结果页、不改变现有答题和结算逻辑，先让数据库独立可审阅。

## Result contract

- `parentTypeId`：每个现实原子分支必须引用一个父母类型，并继续关联现有身份卡。
- 主型：由 10 个已选现实分支的父母类型信号计算，展示一个最能概括选择倾向的类型。
- 影子型：由遗憾分支、时间影响和关系代价中最突出的类型计算，展示“这种爱可能带来的代价”。
- 时间账单：优先使用真实问卷中的时间窗口、持续年限或明确错过；没有明确数字时展示原始影响，不虚构数字。
- 幻想身份：继续使用分支表中的 `fantasyBranchId`，并显示对应的身份卡。

## Database model

- 数据库记录 16 个父母类型、4 个分析维度、30 个原子分支和组合规则。
- 不把 3¹⁰ 个排列组合逐条写死。每个选择提供信号，系统将 10 个选择的信号相加，再计算主型和影子型；这样后续增加场景不需要重写所有组合。
- 每个原子分支包含：为什么归入该父母类型、父母做了什么、孩子可能走向哪里、时间账单、影子风险，以及现有身份卡引用。
- 组合分析分成五步：读取已选分支、聚合信号、确定主型/影子型、组装成长/遗憾/幻想三类卡、生成可读叙事。
- AI 只负责最后的叙事组织，不能创造问卷中没有的年份、成就、身份或因果；所有结果必须保留 `selectedBranchIds`、类型、卡片和时间来源。

## Completion conditions

- 16 个父母类型各有唯一 ID、标题、释义和结果语气。
- 30 个现实原子分支全部引用有效的父母类型，并继续关联现有身份卡；16 个类型都至少被一个原子分支使用。
- 结果页首要视觉层级为“你是：X父母”，而不是卡牌数量。
- 结果页仍能显示现实后来、时间影响和幻想身份；三类卡数量继续准确统计。
- 缺失或非法父母类型引用会阻止数据加载并显示错误。
- 当前阶段只要求数据库文件通过 JSON 校验并可供人工审阅；算法和 UI 接入留到审阅通过后。

## Validation plan

- 用 JSON 解析和自定义数据校验确认 16 个类型、30 个卡片引用和 30 条分支完整。
- 用 Node 语法检查 `app.js` 与 `gamification-engine.js`。
- 用一个固定的 10 题选择集合确认主型、影子型和时间账单均来自数据表，不依赖页面内硬编码映射。
- 仅提交代码和数据变更；交互测试由用户自行进行。
